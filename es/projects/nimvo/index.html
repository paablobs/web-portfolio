Nimvo

Finanzas personales local-first con SQLite WebAssembly en un Web Worker, exportación de archivos cifrados, cálculos en centavos enteros y pruebas automatizadas.

  • React
  • TypeScript
  • SQLite / WASM
  • Web Workers
  • Web Crypto
  • Playwright
Código fuenteVer aplicación

Problema y alcance

Administrar ingresos, gastos fijos y gastos diarios sin cuentas ni una base remota. Mantener los datos financieros en un archivo protegido con contraseña y bajo control del usuario.

Implementación y arquitectura

React llama a un protocolo tipado de worker en lugar de ejecutar SQL desde los componentes. Un Web Worker ejecuta sql.js/SQLite en memoria, con repositorios de dominio, transacciones y migraciones versionadas.

La base se exporta a un contenedor .nimvo versionado mediante Web Crypto: AES-256-GCM y PBKDF2-HMAC-SHA-256. Los datos financieros no se guardan en localStorage; las preferencias de presentación sí.

Decisiones y compromisos

Los importes usan centavos enteros en lugar de aritmética de punto flotante. Marcar un gasto fijo como pagado cambia su estado pendiente, no el saldo, porque su importe ya estaba reservado.

El archivo local evita alojar los datos financieros en un servicio, pero deja el guardado, los respaldos y la custodia de la contraseña a cargo del usuario. Chromium permite escribir en un archivo elegido; otros navegadores pueden descargar una copia.

Pruebas y verificación

Vitest y React Testing Library cubren cálculos monetarios, repositorios, migraciones, contenedores cifrados y componentes. Las suites Playwright cubren flujos en Chromium y Firefox, archivos, navegación con teclado y comprobaciones básicas de accesibilidad.

Las pruebas incluyen archivos alterados o truncados y contraseñas incorrectas, no solo cifrado y descifrado exitosos. Las comprobaciones automatizadas no equivalen a una auditoría de seguridad independiente.

Limitaciones actuales

Sin sincronización propia, colaboración ni recuperación de contraseña. Los cambios sin guardar pueden perderse y no se reconcilian ediciones paralelas de copias del archivo.

Una pestaña completamente cargada puede operar sin red, pero no hay service worker ni caché PWA: abrir o recargar la aplicación sigue requiriendo que el host esté disponible.
