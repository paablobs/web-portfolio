Nout

Offline-first notes with optional Firestore sync. Repository-based persistence, sign-in migration, Firebase permission tests and Playwright E2E workflows.

  • React
  • TypeScript
  • Firestore
  • TipTap
  • Vitest
  • Playwright
Source codeLive app

Problem & scope

Take and organize rich-text notes without requiring an account, while offering cloud synchronization for users who sign in.

Implementation & architecture

React and TypeScript handle the interface, TipTap handles rich-text editing, and repository adapters separate note and folder operations from localStorage and Firestore persistence.

Local data is migrated when a user first signs in. The migration compares edit timestamps, processes writes in batches and tracks migrated records.

Decisions & tradeoffs

Local-first storage keeps account creation optional. Supporting both local and remote data adds migration and reconciliation responsibilities that a cloud-only CRUD interface would avoid.

Migration waits for queued edits and recalculates pending changes before committing. Newer edits take precedence; this is timestamp-based reconciliation, not collaborative text merging.

Testing & verification

Vitest tests cover data-layer behavior. Firebase emulator tests exercise security rules, user isolation and repository integration. Playwright covers offline-only browser workflows.

The repository's CI workflow is configured to run lint, formatting checks, build, unit tests, Firebase tests and E2E tests. Cloud-sync behavior is not comprehensively covered by the offline E2E suite.

Current limitations

Local-only notes depend on browser storage. Cloud synchronization requires an account and connectivity, and failures still need to be handled explicitly.

Timestamp-based reconciliation does not preserve both versions of every conflicting edit. This project does not claim lossless collaborative editing or guaranteed recovery from every network failure.
