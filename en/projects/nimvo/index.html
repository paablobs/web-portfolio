Nimvo

Local-first personal finances with SQLite WebAssembly in a Web Worker, encrypted file exports, integer-cent calculations and automated tests.

  • React
  • TypeScript
  • SQLite / WASM
  • Web Workers
  • Web Crypto
  • Playwright
Source codeLive app

Problem & scope

Manage monthly income, recurring expenses and daily spending without accounts or a remote database. Keep the financial data in a password-protected file controlled by the user.

Implementation & architecture

React calls a typed worker protocol rather than issuing SQL from components. A Web Worker runs sql.js/SQLite in memory, with domain repositories, transactions and versioned migrations.

The database is exported into a versioned .nimvo container using Web Crypto: AES-256-GCM and PBKDF2-HMAC-SHA-256. Financial data is not stored in localStorage; presentation preferences are.

Decisions & tradeoffs

Amounts use integer cents instead of floating-point arithmetic. Marking a fixed expense as paid changes its pending status, not the balance, because the amount was already reserved.

A local file removes the need for a hosted financial-data service, but makes saving, backups and password custody the user's responsibility. Supported Chromium browsers can write to a chosen file; other browsers can download a copy.

Testing & verification

Vitest and React Testing Library cover money calculations, repositories, migrations, encrypted containers and component behavior. Playwright suites cover Chromium and Firefox flows, file handling, keyboard navigation and basic accessibility checks.

The tests include altered or truncated files and incorrect passwords, not only successful encryption and decryption. Automated checks do not constitute an independent security audit.

Current limitations

No built-in synchronization, collaboration or password recovery. Unsaved changes can be lost, and parallel edits to separate file copies are not reconciled.

A fully loaded tab can operate without a network connection, but there is no service worker or PWA cache: opening or reloading the app still requires the host to be available.
